# ТЗ: ORRERY v3 — от плоской заглушки к настоящему 3D-симулятору

Документ состоит из трёх частей: аудит текущей версии, целевая архитектура, план работ по фазам с критериями приёмки.

---

## Часть 1. Аудит текущей версии (v2, Canvas 2D)

### 1.1 Критические баги математики

| # | Проблема | Причина в коде | Следствие |
|---|---|---|---|
| B1 | Планеты летают не по кругу, а по диагональному отрезку | В орбите заданы `y = sin(a)*r*0.55` и `z = sin(a)*r*0.45`, то есть Y и Z линейно зависимы. Настоящая орбита требует `x = cos(a)*r`, `z = sin(a)*r`, `y = 0` | Орбита вырождается в наклонный эллипс, физика выглядит неправильно |
| B2 | Кольца орбит не совпадают с планетами при вращении | Кольца рисуются через `ctx.ellipse(..., rotation = ry)`, а планеты — через матрицу поворота по двум осям. Наклон камеры `rx` на кольца не влияет вообще | При вращении сцены планеты «съезжают» со своих орбит |
| B3 | Нет глубины | `project()` считает `depth`, но результат нигде не используется. Сортировка идёт по экранной координате Y | Дальние планеты не уменьшаются, не затемняются, не заходят за Солнце |
| B4 | Клик срабатывает после перетаскивания | В `pointerup` дистанция считается от `lastX/lastY`, которые обновляются на каждом `pointermove`, поэтому «сдвиг» всегда близок к нулю | После любого вращения случайно выбирается планета |
| B5 | Скорости планет выдуманы | `t * (0.18 / (i + 1))` вместо периодов обращения | Меркурий и Нептун движутся почти одинаково, это не солнечная система |
| B6 | Кольцо Сатурна нарисовано в экранных координатах | Жёстко `ellipse(x, y, 22, 7, 0.18)` для индекса 5 | Кольцо не наклоняется вместе со сценой и не масштабируется зумом |
| B7 | Часы симуляции фейковые | Строка собирается из `08:` + остаток от деления | Нет привязки к реальной дате и эфемеридам |

### 1.2 Мёртвые и полумёртвые элементы интерфейса

- Страница **Настройки** — витрина: четыре строки статичного текста, ни один параметр не редактируется.
- Кнопка **Сбросить настройки** переключает тумблеры по индексу `i < 2`, что развалится при добавлении любого нового тумблера.
- Индикатор `buttonStatus` меняется один раз и никогда не возвращается в исходное состояние.
- Страница **Наблюдения** — декоративная: «таймлайн» это две CSS-точки, ездящие по кругу, без связи с симуляцией.
- Тумблер **Auto rotate** насильно включается при заходе на страницу наблюдений и не выключается обратно.
- Кнопка сворачивания панели не пересчитывает размер канваса, сцена остаётся в старых пропорциях.

### 1.3 Технические ограничения

- Ресайз слушает только `window`, а не контейнер: при смене раскладки канвас растягивается.
- Нет pinch-зума, при этом `touch-action: none` блокирует нативные жесты.
- Нет состояния в URL и в localStorage: перезагрузка обнуляет всё.
- Нет клавиатурного управления и обработки `prefers-reduced-motion`.
- Канвас не имеет текстовой альтернативы для скринридера.
- Подписи планет перекрываются при сближении объектов.

## Часть 2. Целевая архитектура (v3)

### 2.1 Стек

- **Three.js (WebGL2)** как основной рендерер, вместо Canvas 2D.
- **OrbitControls** с инерцией: `enableDamping = true`, `dampingFactor ≈ 0.06`, ограничение `minDistance` / `maxDistance`, `maxPolarAngle` чуть меньше π.
- **Raycaster** для выбора объектов, с увеличенными невидимыми сферами-хитбоксами для мелких планет.
- **CSS2DRenderer** для подписей: HTML-лейблы поверх сцены, автоматическое скрытие перекрытых, приоритет по расстоянию до камеры.
- **EffectComposer**: `RenderPass` + `UnrealBloomPass` для короны Солнца, опциональный `SMAAPass`.
- Модульная структура: `core/` (сцена, рендер-луп, камера), `bodies/` (данные и фабрики тел), `ui/` (панели, страницы, роутер), `state/` (единый стор + подписки).

### 2.2 Модель данных небесного тела

Каждое тело описывается орбитальными элементами, а не индексом в массиве:

```
{
  id, name, nameRu, type,
  a,            // большая полуось, а.е.
  e,            // эксцентриситет
  i,            // наклонение орбиты, градусы
  omega, Omega, // аргумент перицентра и долгота восходящего узла
  M0,           // средняя аномалия на эпоху J2000
  period,       // сидерический период, сутки
  radiusKm, axialTilt, rotationPeriod,
  texture, ringTexture, moons: [...]
}
```

Позиция считается через решение уравнения Кеплера (`M = E - e·sin E`, 4-5 итераций Ньютона), затем перевод в гелиоцентрические координаты. Это даёт настоящие эллипсы, наклонения и корректные относительные скорости.

### 2.3 Визуальное качество

- Сферы `SphereGeometry(1, 64, 32)` с текстурами (diffuse + normal для каменистых планет).
- **Солнце**: эмиссивный материал, шейдерная корона на билборде, `PointLight` в центре сцены с физически затухающей интенсивностью.
- **Тени и терминатор**: планеты освещаются только от Солнца, ночная сторона реально тёмная.
- **Земля**: слой облаков отдельной прозрачной сферой, ночные огни через emissive-карту.
- **Сатурн**: `RingGeometry` с альфа-картой, наклон 26.7°, кольцо в 3D, а не в экранных координатах.
- **Пояс астероидов**: `InstancedMesh` на 2000-4000 объектов с рандомизированным разбросом по эксцентриситету и наклонению.
- **Звёздное небо**: `Points` на 8-10 тысяч звёзд со сферическим распределением и вариацией цвета и яркости.
- **Орбитальные линии**: `LineLoop` из 256 точек, посчитанных по тем же кеплеровским элементам, что и позиция планеты. Гарантия совпадения линии и тела.
- **Хвост движения**: затухающий след за выбранной планетой.

### 2.4 Камера и управление

Три режима, переключаемые из интерфейса и с клавиатуры:

1. **Orbit** — свободное вращение вокруг центра системы.
2. **Follow** — камера привязана к выбранной планете, орбита вращается вокруг неё, Солнце уезжает вбок.
3. **Cinematic** — медленный автоматический облёт с плавным переходом между телами.

Переход между объектами: анимация позиции камеры и точки фокуса через `cubic-bezier(0.16, 1, 0.3, 1)`, длительность 900 мс, без рывков и без bounce.

Вход: мышь (drag, wheel, click), тач (drag, pinch, tap), клавиатура (стрелки — поворот, `+` / `-` — зум, `Space` — пауза, `1`-`8` — выбор планеты, `R` — сброс, `F` — follow-режим, `Esc` — снять выделение).

## Часть 3. План работ

### Фаза 1. Фундамент (обязательная база)

1. Подключить Three.js, вынести рендер-луп с `requestAnimationFrame` и дельта-таймом.
2. Реализовать кеплеровскую математику орбит, покрыть проверкой: период Земли даёт полный оборот ровно за 365.25 симуляционных суток.
3. Собрать 8 планет + Солнце как настоящие меши со светом от `PointLight`.
4. OrbitControls с инерцией, ограничениями и pinch-зумом.
5. Raycaster-выбор с корректным разделением drag и click: запоминать `downX/downY` в `pointerdown` и сравнивать с ними, а не с промежуточными координатами.
6. `ResizeObserver` на контейнер сцены плюс адаптивный `devicePixelRatio` (потолок 2).

**Критерий приёмки:** сцена вращается со всех сторон без разъезда орбит и планет, клик после перетаскивания ничего не выделяет, Меркурий заметно быстрее Нептуна.

### Фаза 2. Живой интерфейс

1. Единый стор состояния, все панели читают из него и подписываются на изменения. Никаких прямых мутаций DOM из разных мест.
2. Страница **Настройки** становится рабочей: качество рендера (низкое / среднее / высокое), bloom вкл-выкл, показ орбит, показ подписей, единицы измерения (км / а.е.), реалистичный или схематичный масштаб, тема подписей.
3. Сброс настроек работает по ключам стора, а не по индексам DOM-элементов.
4. Панель управления при сворачивании корректно пересчитывает канвас.
5. Роутинг через hash (`#/system`, `#/catalog`, `#/observe`, `#/settings`) плюс сохранение состояния в localStorage: выбранная планета, скорость времени, тумблеры.
6. Состояния интерфейса: загрузка текстур со скелетоном, ошибка WebGL с понятным текстом и ссылкой на диагностику, пустой результат поиска в каталоге.

**Критерий приёмки:** каждый переключатель и каждая кнопка на всех четырёх страницах меняют что-то видимое; после перезагрузки состояние восстанавливается; страницы открываются по прямой ссылке.

### Фаза 3. Контент и глубина

1. Спутники: Луна, Фобос и Деймос, галилеевы спутники Юпитера, Титан и Энцелад, Тритон. Со своими орбитами вокруг планет.
2. Пояс астероидов и объекты пояса Койпера.
3. Карточка тела: состав, температура, гравитация, продолжительность суток, число миссий, интересный факт. Данные в отдельном JSON, а не в разметке.
4. **Режим сравнения**: две планеты рядом в одном масштабе, диаграмма радиусов и массы.
5. **Шкала времени**: скраббер с реальными датами, кнопки «сегодня», «перигелий Марса», «великое противостояние», «парад планет». Возможность отмотать на годы вперёд и назад.
6. **Экскурсия**: последовательность из 9 остановок с текстом, автоматическим перелётом камеры и кнопками «дальше» и «пропустить».

**Критерий приёмки:** страница «Наблюдения» перестаёт быть декорацией и показывает реальные события системы, привязанные к дате симуляции.

### Фаза 4. Полировка и производительность

1. LOD для планет: снижение сегментов сферы на удалении, отключение облаков и колец на дальнем плане.
2. Адаптивное качество: если FPS падает ниже 45 на протяжении секунды, автоматически снижать `pixelRatio` и отключать bloom, с уведомлением в интерфейсе.
3. Заморозка рендер-лупа при `document.hidden` и при уходе сцены с активной страницы.
4. Поддержка `prefers-reduced-motion`: отключение автовращения, cinematic-режима и анимации перелётов.
5. Доступность: канвас получает `role="application"`, описание сцены и живой текстовый дубль текущего состояния для скринридера; фокус-кольца на всех интерактивных элементах; тач-цели минимум 44 px.
6. Подписи с разрешением коллизий: при перекрытии остаются подписи ближайших к камере тел.
7. Мобильная раскладка: панель превращается в нижний лист с ручкой перетаскивания, а не в блок под сценой.

**Критерий приёмки:** стабильные 60 FPS на десктопе и не ниже 30 на среднем телефоне, полное управление с клавиатуры, ни одного элемента без видимого состояния фокуса.

### Фаза 5. Приятные излишества

- Режим «Что если»: изменить массу Солнца или радиус орбиты и увидеть, как меняется период.
- Траектории аппаратов: Вояджеры, Новые горизонты, Паркер.
- Скриншот сцены в PNG с подписью даты симуляции.
- Прямые ссылки на состояние: `#/system?body=mars&date=2027-03-14&zoom=1.8`.
- Звуковой слой: тихий эмбиент и деликатный отклик на выбор тела, по умолчанию выключен.

## Порядок реализации

Фазы 1 и 2 обязательны и делаются подряд: без них проект остаётся презентацией, а не симулятором. Фаза 3 даёт содержательную ценность, фаза 4 превращает демо в продукт, фаза 5 добавляется по желанию.

## Что считается готовым

Проект готов, когда выполняется всё сразу: орбиты соответствуют кеплеровской модели, камера управляется мышью, тачем и клавиатурой без артефактов, каждая кнопка и каждый тумблер имеют видимый эффект, состояние живёт в URL и localStorage, сцена держит 60 FPS на десктопе и корректно деградирует на слабых устройствах.
